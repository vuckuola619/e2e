## Curation lessons carried into the skill

The research supports a small, explainable integration surface:

- keep one router and one canonical evidence and decision authority;
- require recursive resource closure, source identity, license scope, and notices before reuse;
- route UI guidance only when a UI is applicable and keep visual review separate from accessibility and runtime proof;
- keep tool status, producer status, execution status, evidence validity, and canonical check status distinct;
- preserve raw context and an ordered loss manifest; expose graph freshness and coverage and use direct-source fallback when authorized;
- treat mixed or unknown licenses as review blockers for copying or vendoring, while original adapters can remain reference-only;
- treat issue text, documents, web pages, tool output, model output, and imported files as untrusted inputs;
- requalify affected modules after source, resource, license, permission, protocol, host, transform, or normative-reference changes.

Every observed lesson is a design input. It is not a claim that an upstream package is installed, supported, secure, complete, or compatible with a particular host.
